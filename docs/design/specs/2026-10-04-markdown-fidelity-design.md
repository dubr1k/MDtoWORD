# Верность Markdown, оформление документа, MCP и обратное направление (1.2)

**Дата:** 2026-10-04
**Статус:** реализовано

## Задача

Аудит 1.1.1 стресс-документом (≈40 конструкций Markdown, 147 типичных
LaTeX-формул из текстов LLM, просмотр страниц через officecli и LibreOffice)
нашёл дефекты, видные в любом реальном документе:

- нумерация списков сквозная на весь документ: все абзацы списков делили один
  `numId` стиля `List Number`, вложенность задавалась только отступом;
- второй абзац пункта становился новым пунктом;
- раздел сносок делил счётчик со списками («11. [1]»), текст сноски уходил
  отдельным абзацем;
- изображения не масштабировались (3000 px → 1058 мм на странице 216 мм);
- YAML front matter превращался в линию и заголовок H2;
- ссылки `[…](#раздел)` писались внешними и не работали;
- одиночный перенос строки становился разрывом строки — текст с hard-wrap
  рассыпался на рваные строки;
- в ячейках таблиц терялось форматирование, ссылки и формулы;
- страница US Letter, язык документа `en-US`;
- Word → Markdown переносил все таблицы в конец документа и терял текст
  гиперссылок.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Списки | Свой `w:num` на каждый список Markdown (`ooxml.ListNumbering`), уровень — `w:ilvl`, старт — `w:startOverride` | Иначе Word продолжает один счётчик через весь документ |
| Абзацы-продолжения | Без номера, отступ на уровень текста пункта; блок, с которого начинается пункт (код, формула), получает пустой нумерованный абзац | Так пункт не теряет номер и не плодит лишние |
| Сноски | Настоящие сноски Word (`footnotes.xml`) по умолчанию; режим `section` — прежний раздел в конце, но без общего счётчика | Для академических текстов это главное ожидание |
| Одиночный перенос | Пробел (CommonMark/GFM) по умолчанию; `line_breaks="preserve"` — разрыв | Hard-wrap — норма для исходников и для текста от LLM |
| Перенос с выключкой | `w:doNotExpandShiftReturn` в `settings.xml` | Word растягивал строку перед Shift+Enter |
| Изображения | Масштаб в ширину колонки (с запасом 1 %) и 80 % высоты, пропорции сохраняются; SVG — `asvg:svgBlip` с PNG-заглушкой; WebP и прочее — через Pillow в PNG | Без этого картинка выходит за страницу |
| Подписи | Одиночная картинка с alt/title — рисунок с подписью «Рисунок N — …» / «Figure N: …», абзац `Table:`/`Таблица:` рядом с таблицей — подпись над таблицей; номер — поле `SEQ` | ГОСТ 7.32 и привычка pandoc |
| Якоря | Слаги заголовков по алгоритму GitHub считаются заранее, до рендера — ссылка может стоять раньше заголовка | Ссылки вперёд — обычное дело |
| Front matter | Плоский разбор YAML без новой зависимости: заголовочный блок и свойства документа | `PyYAML` ради пяти ключей не нужен |
| HTML | `html=True`; белый список строчных тегов в форматирование, `<br>`, `<img>`, `<a>`; блоки — текстом с абзацами; прочее вырезается с одним предупреждением на тег | В docx ничего не исполняется, а текст терять нельзя |
| Пресет ГОСТ | A4, поля 30/15/20/20, интервал 1,5, абзацный отступ 1,25 см, заголовки в кегль текста, номер страницы, подписи по ГОСТ | Основной сценарий пользователей |
| Шаблон | `template=` — стили, поля, колонтитулы берутся из .docx, тело очищается, размер шрифта не штампуется в run'ы | Как `--reference-doc` у pandoc |
| Предупреждения | `ConversionWarning` — подкласс `str` с `code` и `line` | GUI и тесты работают со строками как раньше, MCP отдаёт структуру |
| Удалённые картинки | `safe_fetch`: только глобально маршрутизируемые адреса, подключение к проверенному IP, ручные редиректы с повторной проверкой, лимит размера потоково | Закрывает SSRF через редирект и DNS rebinding |

## MCP

- Инструменты асинхронные, файлы обрабатываются в рабочем потоке, после
  каждого — уведомление о прогрессе.
- Аннотации (`readOnlyHint`, `destructiveHint`, `openWorldHint`).
- Новые инструменты `check_latex` и `inspect_docx`, ресурс
  `mdtoword://guide/markdown`, prompt `prepare_markdown_for_word`.
- Предупреждения — объекты `{message, code, line}`. Это несовместимое
  изменение схемы для клиентов, читавших строки.
- `pyproject.toml` с `mdtoword-mcp`: установка `pip install ".[mcp]"` вместо
  `cwd`/`PYTHONPATH`. Отказ из спеки 2026-07-21 («избыточно ради одного
  скрипта») пересмотрен: это была первая строка раздела «Неполадки».

Отказы спеки 2026-07-21 по общему sandbox, флагу `overwrite` и HTTP-транспорту
остаются в силе.

## Структура кода

Пять модулей выросли до 1200–2400 строк, и их разбили на пакеты — чистым
рефакторингом. Перед разбиением сняли «золотой» эталон: XML документов и
предупреждения для ≈150 Markdown-файлов в двух наборах опций, Markdown
обратного направления, OMML и обратный LaTeX для 147 формул. После
разбиения вывод совпал байт в байт.

| Пакет | Модулей | Как устроен |
|---|---|---|
| `gfm_renderer/` | 17 | Один класс `GfmDocxRenderer`, собранный из миксинов по задачам поверх общего состояния `RendererState`; диспетчер блочных токенов — таблица «тип токена → обработчик» |
| `latex_omml/` | 18 | Токенизатор, рекурсивный разбор, обработчики команд по видам (алфавиты, операторы, декорации, скобки, пробелы), окружения, таблицы символов; `_parse_command` — таблица диспетчеризации с прежним порядком приоритета |
| `docx_to_markdown/` | 25 | Небольшие классы-соавторы с явными входами (обход, блоки, списки, цитаты, таблицы, медиа, сноски, подписи, строчный текст, экранирование), без миксинов |
| `omml_latex/` | 7 | Обработчики элементов OMML через таблицу, таблицы символов |
| `ooxml/` | 11 | По модулю на примитив: нумерация, сноски, ссылки и закладки, поля, страница, изображения, SVG, заливки и границы |
| `mcp_server/` | 12 | Экземпляр сервера, модели, параметры, пути и шаблоны, фабрика конвертеров, пакетный запуск, по модулю на группу инструментов, гайд |
| `gui/` | 3 | Виджеты перетаскивания и тексты интерфейса; окно осталось в `app.py` |

Публичные пути импорта прежние (`mdtoword.gfm_renderer.GfmDocxRenderer`,
`mdtoword.latex_omml.latex_to_omml`, `python -m mdtoword.mcp_server`, …).
Тесты, которые патчили имена, теперь патчат модуль, где имя действительно
используется, — например, `mdtoword.gfm_renderer.images.fetch_image`. Старые
пути намеренно не реэкспортируются: патч по ним падает с `AttributeError`,
а не проходит молча. Крупнейший модуль после разбиения — `app.py`, 469 строк.

## Что сознательно не делается

- Подсветка синтаксиса в блоках кода — потребовала бы Pygments и цветной
  текст, а документ намеренно чёрно-белый.
- Эмодзи-шорткоды (`:rocket:`) остаются текстом.
- Таблица внутри сноски — текстом с предупреждением: python-docx не создаёт
  таблицы в частях, отличных от тела документа.
